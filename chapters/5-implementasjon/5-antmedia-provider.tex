\section{AntMediaProvider}
\label{sec:antmedia-provider}

\texttt{AntMediaProvider} kommuniserer mot AntMedias REST-API via en
typed \texttt{HttpClient} med \texttt{AntMediaAuthHandler} bakt inn i
HTTP-pipelinen. Ved oppretting sendes navn og den hardkodede typen
\texttt{liveStream} til \texttt{broadcasts/create}. Responsen mappes til
\texttt{VideoRoom} med strøm-spesifikke felter: \texttt{StreamUrl} for
HLS-avspilling, \texttt{RtmpUrl} for RTMP-ingest og tre
seertellere per protokoll. Start og stopp er POST-kall uten body mot
\texttt{broadcasts/\{id\}/start} og \texttt{broadcasts/\{id\}/stop}.
WebRTC-tokens hentes i to faser: først verifiseres at rommet eksisterer,
deretter genereres et token med 90 sekunders levetid via
\texttt{broadcasts/\{id\}/token?expireDate=\{ts\}\&type=\{type\}}.
Tokensetting mangler et dedikert endepunkt i AntMedia, så løsningen ble å
legge tokenet i \texttt{metaData}-feltet via PUT mot
\texttt{broadcasts/\{id\}}.

\texttt{AntMediaAuthHandler} signerer JWT-tokens lokalt med HMAC-SHA256
og cacher dem i fem minutter. Token-genereringen bruker double-check
locking for å unngå at samtidige forespørsler genererer hvert sitt token
når cachen utløper, som vist i listing~\ref{lst:antmedia-auth}.

\begin{lstlisting}[language={[Sharp]C}, label=lst:antmedia-auth,
  caption={Double-check locking i AntMediaAuthHandler.}]
var now = DateTimeOffset.UtcNow.ToUnixTimeSeconds();

if (!string.IsNullOrEmpty(_cachedToken)
        && _tokenExpiry > now + TokenRefreshBufferSeconds)
    return _cachedToken;

await _semaphore.WaitAsync(cancellationToken);
try
{
    if (!string.IsNullOrEmpty(_cachedToken)
            && _tokenExpiry > now + TokenRefreshBufferSeconds)
        return _cachedToken;

    var expiry = now + TokenLifetimeSeconds;
    var key = new SymmetricSecurityKey(
        Encoding.UTF8.GetBytes(_config.JwtSecret));
    var creds = new SigningCredentials(key, SecurityAlgorithms.HmacSha256);
    var descriptor = new SecurityTokenDescriptor
    {
        Claims = new Dictionary<string, object>
            { { "exp", expiry }, { "iat", now } },
        SigningCredentials = creds
    };
    var handler = new JwtSecurityTokenHandler();
    _cachedToken = handler.WriteToken(handler.CreateToken(descriptor));
    return _cachedToken;
}
finally { _semaphore.Release(); }
\end{lstlisting}

Tokenet inneholder kun \texttt{iat} og \texttt{exp} — AntMedia krever
ikke subjekt- eller audience-claims for server-til-server-autentisering.
Manglende \texttt{JwtSecret} i konfigurasjon kaster
\texttt{ConfigurationException}, som \texttt{GlobalExceptionHandler}
oversetter til HTTP~503. Feil fra AntMedia-APIet mappes av den private
hjelperen \texttt{EnsureSuccessOrThrowAsync}: 404 gir
\texttt{NotFoundException}, alt annet gir \texttt{ExternalServiceException}
med original statuskode bevart.
