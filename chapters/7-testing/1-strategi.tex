\section{Teststrategi}
\label{sec:teststrategi}
Testarbeidet var organisert i tre nivåer: enhetstester for isolerte
komponenter, integrasjonstester for HTTP-laget og manuell testing mot
faktiske testmiljøer. Alle automatiserte tester kjørte via GitHub Actions
ved push til \texttt{main}, \texttt{develop} og feature-brancher, samt
ved pull requests.

Den ordinære testsuiten på leveransegrenen omfattet 133 tester, og alle
passerte ved hver kjøring. På den separate valideringsgrenen
\texttt{feature/provider-validation} ble testsettet utvidet til 166
tester for arkitekturvalidering (jf. delkapittel~\ref{sec:provider-validering});
dette inngår ikke i hovedleveransen mot HDO.

Testrammeverket var xUnit med Moq for mocking. AntMedia, NHN Video og
Keycloak var fullstendig mocket i alle automatiserte tester, slik at ingen
tester krevde tilgang til ekte backend-miljøer. To hjemmelagde
testkomponenter dekket dette: en lokal
\texttt{StubHttpMessageHandler}-implementasjon for enhetstesting av
HTTP-klienter (jf.\ delkapittel~\ref{sec:enhetstester}) og
\texttt{CustomWebApplicationFactory} for in-memory integrasjonstesting
(jf.\ delkapittel~\ref{sec:integrasjonstester}).

Målet var ikke å bevise produksjonsklarhet, men å verifisere at
POC-et oppfylte kravspesifikasjonen og at arkitekturen støttet
utvidelse med nye videomotorer. Teststrategien hadde fire konkrete mål:
å verifisere kjerneoperasjonene i krav F1.1--F1.5, å teste sentrale feil-
og sikkerhetsscenarier, å kontrollere integrasjon mot faktiske AntMedia-
og NHN-testmiljøer, og å måle hvor mye kjernelogikk som måtte endres ved
innføring av nye providere.

\subsection{Reprodusere testresultatene}
\label{subsec:reprodusere-tester}
For å reprodusere testresultatene, se \texttt{README} i prosjektets
GitHub-repositorium (jf. vedlegg~\ref{app:kildekode}). Testene krevde
.NET~10 SDK; ingen eksterne tjenester var nødvendige siden alle
avhengigheter var mocket i testmiljøet.
