\section{Teststrategi}
\label{sec:teststrategi}
Testarbeidet var organisert i tre nivåer: enhetstester for isolerte
komponenter, integrasjonstester for HTTP-laget, og manuell testing mot
faktiske testmiljøer. Alle automatiserte tester kjørte via GitHub Actions
ved push til \texttt{main}, \texttt{develop} og feature-brancher, samt ved
pull requests.
Den ordinære testsuiten på leveransegrenen omfattet 133 tester, og alle passerte ved
hver kjøring.
På den separate valideringsgrenen \texttt{feature/provider-validation} ble testsettet
utvidet til 166 tester for arkitekturvalidering (se avsnitt~\ref{sec:provider-validering});
dette inngår ikke i hovedleveransen mot HDO.

Testrammeverket var xUnit med Moq for mocking. Eksterne tjenester
(AntMedia, NHN Video og Keycloak) var fullstendig mocket i alle
automatiserte tester, slik at ingen tester krevde tilgang til ekte
backend-miljøer. To hjemmelagde infrastrukturkomponenter dekket dette:
\texttt{StubHttpMessageHandler} for enhetstesting av HTTP-klienter
(jf.\ avsnitt~\ref{sec:enhetstester}) og \texttt{CustomWebApplicationFactory}
for in-memory integrasjonstesting (jf.\ avsnitt~\ref{sec:integrasjonstester}).

Målet med testingen var ikke å bevise produksjonsklarhet, men å verifisere
at proof-of-conceptet oppfylte kravspesifikasjonen og at arkitekturen
støttet utvidelse med nye videomotorer. Teststrategien hadde derfor fire
konkrete mål: å verifisere kjerneoperasjonene i krav F1.1--F1.5, å teste
sentrale feil- og sikkerhetsscenarier, å kontrollere integrasjon mot
faktiske AntMedia- og NHN-testmiljøer, og å måle hvor mye kjernelogikk
som måtte endres ved innføring av nye providere.

\subsection{Reprodusere testresultatene}
\label{subsec:reprodusere-tester}
Testene kunne kjøres lokalt med følgende kommandoer. Coverage-rapporten
krever \texttt{dotnet-reportgenerator-globaltool}, som installeres første
gang.

\begin{lstlisting}[language=bash, caption={Kjøre testsuiten med coverage}]
# Klon repoet
git clone https://github.com/Gruppe-213/HDO-VideoAPI.git
cd HDO-VideoAPI

# Kjør alle tester
dotnet test

# Installer reportgenerator (ignorer feil hvis allerede installert)
dotnet tool install -g dotnet-reportgenerator-globaltool || true

# Kjør med coverage-innsamling
dotnet test --collect:"XPlat Code Coverage" \
  --results-directory ./coverage

# Generer lesbar rapport
reportgenerator \
  "-reports:./coverage/**/coverage.cobertura.xml" \
  "-targetdir:./coverage/report" \
  "-reporttypes:TextSummary"
cat ./coverage/report/Summary.txt
\end{lstlisting}

Testene krevde .NET~10 SDK. Ingen eksterne tjenester var nødvendige siden
alle avhengigheter var mocket i testmiljøet.
