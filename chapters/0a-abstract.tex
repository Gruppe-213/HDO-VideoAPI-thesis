\chapter*{Abstract}
\gls{hdo} drifter videoløsninger som er beslutningsstøtte for \gls{amk}
og \gls{lvs} i Norge. Løsningene bygger på to videomotorer, AntMedia
Server og \gls{nhn} Video, som dekker det samme behovet, men har ulike
\gls{api}-er, autentiseringsmekanismer og domenemodeller. Parallell
integrasjon mot begge motorene øker kompleksiteten i drift og
videreutvikling, og hever terskelen for å bytte leverandør eller legge
til nye videomotorer.

Oppgaven undersøker om en \gls{provider}-basert \gls{mellomvare} kan
gi HDO ett felles API for håndtering av videorom, mens logikk som er
spesifikk for hver videomotor holdes adskilt fra resten av systemet.
Prosjektet ble gjennomført som et design- og implementasjonsprosjekt.
Løsningen ble utviklet i ASP.NET Core med egne providere for AntMedia
Server og NHN Video, \gls{token}-basert autentisering, Docker-støtte,
helsesjekker, strukturert logging og Prometheus-metrikker.

Evalueringen besto av kravsporing, automatiserte enhets- og
integrasjonstester, ende-til-ende-testing mot HDOs testmiljøer og en
sluttevaluering fra HDO. Arkitekturen dekker kjerneoperasjonene
oppretting, henting og sletting av videorom på tvers av begge motorene,
og provider-laget isolerer det meste av den backend-spesifikke
logikken. Full standardisering er likevel vanskelig når videomotorene
bygger på ulike domenemodeller. Det gjelder særlig start og stopp av
videostrøm, som ikke har samme betydning i AntMedia og NHN Video.

En provider-basert mellomvare reduserer koblingen mellom HDOs
klientsystemer og de underliggende videomotorene, og gjør det enklere
å støtte nye videoplattformer i fremtiden. Resultatet er et
proof-of-concept som viser at arkitekturen er gjennomførbar i praksis.
Skal løsningen tas i produksjon, må den videreutvikles med strengere
autorisasjon, robust tokenvalidering, skaleringstesting og bedre
feilhåndtering mot eksterne videomotorer.
